# 核心方法分析规范

核心方法是科研汇报的最高优先级部分，必须以论文原文为依据，不能凭常识补写论文没有描述的机制。

## 1. 整体框架优先
先展示论文整体框架图，按数据流解释输入、每个模块的输入/输出、参数更新/冻结、训练和推理路径、中间结果如何传递，以及最终输出。自制辅助图应标明「汇报者示意图」，不得冒充原文图。

## 2. 每个关键模块回答六个问题
1. 是什么：模块定义及在整体框架中的位置。
2. 输入/输出：对象、语义及必要的维度。
3. 怎么做：算法步骤、公式、训练目标或决策规则。
4. 为什么：原文明确给出的设计动机；汇报者推断需单独标明。
5. 与其他模块关系：上游输出什么、下游为什么需要它。
6. 代价与限制：额外计算、监督需求、稳定性、适用范围和失败情形。

## 3. 公式讲解
核对原文公式编号、上下文和所有符号；说明每一项计算什么、损失如何作用于模型输出/参数。数值示例须标注「示意例子」，并给出计算过程，不能冒充论文实验。

## 4. 训练、推理和在线更新
明确区分预训练、单次推理、交互中、交互结束后及下一样本到来时的状态。说明参数版本、伪标签/真实标签/用户反馈来源及更新时机。原文未说明的冻结细节不可自行断言。

## 5. 方法页排版
推荐顶部步骤条；左侧核心公式/定义/输入输出；右侧结构图、伪代码或具体示例；底部一句话总结。复杂内容应增加页面，不得只列模块名称或一句「提高鲁棒性」。
